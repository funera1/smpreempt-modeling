# 第1段階: 中断後、Hostだけで完結する直接データ攻撃

実装は `smpreempt/host_attacks.py`。切替条件Gの検証より先に、攻撃の成立を調べる。
新規リクエストや再開を通じてC/SMに処理をさせる攻撃は次段階として分離する。

## 対象の実行

```text
任意の中断前状態Σ∈K0
  → PMの候補Wout（原子的）
  → S-mode Hostによる通常データアクセス
  → 読取または改変が成立した時点で終了
```

T1のSM命令列や到達可能性を探索しない。T2のWoutと、Host内で完結するT3だけを扱う。
T4（resume/invoke）、Win、Gは使わない。
CPUコンテキストの正しい保存とHost GPR初期化は既存Woutの前提として引き継ぐ。
K0は[MODEL.md](MODEL.md)のPC/GPR/M/A/PMPの記号状態と形式制約。
現在のPMPの正しさ、SMのPCマップ、履歴の到達整合性は仮定しない。

保護対象 `R=R_fixed ∪ A` はHost実行中に固定し、現在のPMPから独立して与える。
CLIではAのみ。APIのPM.policyで固定領域も指定できるが、そのポリシーをGとして検査・拒否することはない。

## Hostの操作とまとめた関係

Bare、通常メモリ、固定PMPの下で、Hostが任意アドレス・値を選べるとする。

```text
read(a):  PMPがRを許せば M[a] をHostが観測
write(a,v): PMPがWを許せば M[a] をvへ変更
```

HostはPMP、R、PM保存スロットを変更しない。レジスタはアドレス・書込値を用意するため自由に使える。
HostMemory.closureは任意回の書込を含むフレーム条件を定義する。

```text
H(M,M') := ∀a. ¬PMP_W(a) ⇒ M'[a]=M[a]
```

書込可能なバイトの最終値は任意。これはこのデータ操作抽象化の関係であり、
CSR・例外・命令フェッチを含む実ISAの全Host動作との同値性を主張しない。

PMPとRが不変なら、保護対象に対する最初の直接データアクセスが違反となる。
そのアクセスには対象バイトへの権限が必要なので、長いHost命令列を探索する代わりに、
一つの読取/書込の成立を調べればこの範囲を扱える。
先行するHost算術や通常メモリ操作でアドレスを得る場合も、任意アドレスの選択が包含する。

## 問合せ

Pを中断前PMP、P_HをWout後PMPとし、Host開始の必要条件を

```text
Start := Installable(P,P_H) ∧ PMP_X(P_H,0x1000,4)
```

とする。Host入口のX権限は最小限の条件であり、命令内容やHostの進行を証明しない。
Woutの実命令列・書込順序・PM自身の実行可能性もまだ原子的に抽象化している。

それぞれ独立に以下の存在をZ3に問う。

```text
直接読取:
  K0 ∧ Start ∧ a∈R ∧ PMP_R(P_H,a,1)
  観測値 = M[a]

実際の書換え:
  K0 ∧ Start ∧ a∈R ∧ PMP_W(P_H,a,1) ∧ v≠M[a]
  M' = Store(M,a,v)
```

安全な状態に絞るGや、隔離成立を前提にしない。
読取は保守的な領域ポリシーに対するアクセス成立であり、非干渉性や秘密の意味を判定するものではない。
書換えでは単なる書込権限ではなく、実際に値が変わることを要求する。

## 切替不能と攻撃の分離

startupは、各状態の分類を存在問合せとして個別に出力する。

- host_start: WoutでPMPを設置でき、Host入口にX権限がある状態が存在。
- install_blocked: ロック制約でHost用PMPを設置できない状態が存在。
- entry_not_executable: 設置できるがHost入口にX権限がない状態が存在。
- restore_blocked_after_start: Hostには渡せるが、元PMPへの復元ができない状態が存在。

後三者そのものをデータ攻撃として数えない。
今回はHostだけで完結する攻撃なので、復元不能を攻撃探索の除外条件にしない。
従来のPM API/地点制御が復元不能な切替を事前拒否することとは区別する。
また、startupや各attacksは独立した問合せであり、同一の中断状態を指すとは限らない。

## 実行と出力

```sh
.venv/bin/python -m smpreempt.exploration.explore_system --analysis attacks
```

既定モードもattacks。PMP引継ぎWoutと固定テンプレートWoutを比較する。
両者ともK0の任意Aに対して読取・書換えの反例が存在する。
固定テンプレートは0x8000..0x80ffだけを隔離するため、その外の許可領域にAがあれば攻撃が成立する。

| status | 意味 |
|---|---|
| attack_found | 読取または実際の改変の反例が存在 |
| no_direct_data_attack_in_model | Host開始可能な状態があり、読取/改変の両存在式がunsat |
| host_unavailable | 指定状態集合にHost開始可能な状態がない。安全達成とは扱わない |
| empty_domain | 入力制約が矛盾 |
| unknown | 必要な判定がタイムアウト等で未決着 |

satのwitnessには元PMP、Host PMP、対象アドレス、保護根拠、Host操作を出力する。
読取は具体モデルのLBU、書換えはSBとしてS-modeで再実行する。
projection_replayedは、そのPMPと対象バイトの射影でアクセスを再現したことを意味する。
任意配列全体や中断前SMの実行を再現したことではない。実バイナリのフェッチ/デコードも行わない。

`constrain`で履歴等を絞った場合はconstrained_K0と表示する。
例えばAを固定テンプレートの拒否領域内に限定すれば、直接データ攻撃の両問合せはunsatとなる。
それが実SMの全到達状態を含むかは別の問題。

## この段階に含めない攻撃

再開・新規呼出し・再入を通じた攻撃、ページテーブル/TLB/CSRの効果、
実行権限を通じた観測、MMIO/DMA、マルチhart、マイクロアーキテクチャの側チャネルは扱わない。
保護メモリに対するHostの通常データ読書きに対象を限定した最初のモデルである。
